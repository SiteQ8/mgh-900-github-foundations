# Assessment rubric

Use this as a lightweight completion rubric rather than a high-stakes exam. A learner passes when they can complete the workflow and explain why each step exists.

| Area | Beginning | Developing | Demonstrated |
| --- | --- | --- | --- |
| Repository setup | Repository has little context | README and basic files exist | Repository purpose and next action are immediately clear |
| Commit quality | Changes are broad or unclear | Commit message describes the change | Commit is focused, reversible, and easy to review |
| Branching | Changes are made directly on default branch | Feature branch exists | Branch protects the default branch and has a clear name |
| Pull request | PR lacks intent or verification | PR describes the change | PR supports review with context, evidence, and a next step |
| Issue quality | Issue is vague | Issue includes context | Acceptance criteria are specific and testable |
| Project planning | Work is not organized | Issue appears in a Project | Status reflects the actual next action |
| Actions literacy | Workflow is treated as a black box | Learner can locate the run | Learner can explain trigger, job, step, and result |
| Safety | Sensitive data handling is unclear | Learner recognizes obvious secrets | Learner actively checks for secrets and knows rotation is required |

## Minimum completion evidence

- One meaningful commit.
- One non-default branch.
- One pull request with review context.
- One actionable issue.
- One organized Project item.
- One inspected Actions result.
- One written reflection.

## Optional scoring

If a numeric score is useful, award one point for each evidence item above and one point for each area marked Demonstrated. Use the conversation and explanation as evidence, not only the final repository state.
