# Lab 04 — Issues, Projects, and Actions

**Time:** 45–60 minutes  
**Goal:** Connect planning, collaboration, and automation.

## Part A — Write an actionable issue

Create an issue for an improvement to your practice project. Include a short, specific title; the current behavior or context; the desired outcome; acceptance criteria written as checkboxes; and a label or milestone if your project uses them.

Avoid titles such as Fix stuff. Prefer Add a getting-started example for first-time contributors.

## Part B — Organize the work

Add the issue to a GitHub Project. Create or use a simple workflow with columns or statuses such as Todo, In progress, and Done. Move the issue to the appropriate status.

## Part C — Read an Actions workflow

Open .github/workflows/validate.yml and identify the events that trigger it, the operating system used by the job, the repository checkout step, and the condition that makes the run pass or fail.

Make a small safe change, open a PR, and inspect the workflow result on the PR page.

## Success check

- [ ] Issue describes a problem or improvement another person can act on.
- [ ] Acceptance criteria are testable.
- [ ] Issue is visible in a Project view.
- [ ] You can explain what starts the workflow.
- [ ] You can find the workflow's pass/fail result.
