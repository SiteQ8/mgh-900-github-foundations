# Lab 01 — Repository basics

**Time:** 30–40 minutes  
**Goal:** Create a repository that explains itself.

## Scenario

You are starting a small project. A new collaborator should be able to open the repository and understand its purpose, where to begin, and what a safe contribution looks like.

## Tasks

1. Create a new practice repository, or fork this one.
2. Give it a short, descriptive name.
3. Add a README with the project purpose, a short getting-started section, and the first useful action a contributor should take.
4. Add a .gitignore appropriate to the project, even if it is initially small.
5. Add one file that represents the project: index.html, notes.md, or another safe starter file.
6. Make a commit with a message that describes the change.
7. Inspect the repository's About area and add a one-sentence description.

## Discuss

- What does a repository communicate before anyone reads the code?
- Which files are project content, and which files are collaboration guidance?
- What would you never commit to a public repository?

## Success check

- [ ] The repository has a clear name and description.
- [ ] README tells a new person what to do next.
- [ ] A .gitignore exists.
- [ ] At least one meaningful commit is visible.
- [ ] No secrets or personal data were added.
