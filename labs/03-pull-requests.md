# Lab 03 — Pull requests

**Time:** 45–60 minutes  
**Goal:** Turn a branch into a reviewable proposal.

## Scenario

A teammate needs to review your learner profile before it becomes part of the default branch. A pull request is the conversation and comparison around that proposed change.

## Tasks

1. Push or publish your branch if GitHub asks you to.
2. Open a pull request from student/<your-name> into the default branch.
3. Use the pull request template in this repository.
4. In the description, include the change made, why it was made, how someone can verify it, and one question for the reviewer.
5. Ask a partner to review the PR.
6. Leave one useful review comment that is specific and kind.
7. Respond to the comment or update the file if a change is appropriate.
8. Merge the PR only after the reviewer is satisfied.
9. Delete the feature branch after merging if it is no longer needed.

## Review prompts

- Is the change easy to understand?
- Does it match the stated purpose?
- Is anything missing for the next contributor?
- Are there accidental files, secrets, or unrelated edits?

## Success check

- [ ] PR title explains the change.
- [ ] Description explains intent and verification.
- [ ] At least one review comment is present.
- [ ] The PR was merged or intentionally left open with a clear next step.
