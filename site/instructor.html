Instructor view

Teach the decisions, not just the buttons.

The strongest learning moment is when a learner can say what a GitHub object is protecting, recording, or making visible.

01 / DEMONSTRATE

Show one action

Keep the demo short. Name the intent before you click. Then stop and let learners recreate it.

02 / NARRATE

Ask for the why

Before a commit, branch, PR, or merge, ask what problem the action solves and what evidence will show it worked.

03 / REVIEW

Make feedback specific

Pair learners. Require one comment about clarity, one question, and one explicit next step.

04 / REFLECT

Close the loop

Use the final challenge and reflection to connect the individual features into one collaboration system.

Common friction

Recovery paths that keep momentum.

If this happensTry this
Learner cannot create a repositoryUse a fork or pair with someone who can. The concept matters more than ownership of the first repo.
Learner loses a branchUse the branch selector and compare view. Recreate only after checking whether the work already exists.
PR is too largeAsk what the smallest reviewable change is. Move unrelated edits into a second branch.
Action is unavailableRead the workflow line by line and evaluate the required-file checks manually.

Safety anchor

Never use real passwords, API keys, private customer data, or confidential work files in the exercises. If a secret is exposed, revoke or rotate it immediately; deleting the file is not enough.
