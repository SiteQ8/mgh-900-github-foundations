# Student schedule

This is a flexible one-day plan for **MGH-900: GitHub Foundations — September 10, 2026**. Keep the order because each activity gives you the context for the next one.

| Block | Focus | Your output |
| --- | --- | --- |
| Opening | What GitHub is for; course site tour | A project idea and practice location |
| Part 01 | Repositories, files, and README conventions | A repository with a clear purpose |
| Part 02 | Commits and branches | A focused change on a feature branch |
| Break | Reset and pair up | A review partner |
| Part 03 | Pull requests and review | An opened and reviewed PR |
| Part 04 | Issues, Projects, and Actions | Organized work and an inspected check |
| Close | Final challenge and reflection | A complete GitHub workflow |

## How to use the day

1. Start with the [learner preflight](learner-preflight.md).
2. Follow the labs in order, but keep your project small.
3. Explain the intent of your change before you make it.
4. Ask a partner to review your pull request.
5. Use the [checklist](site/checklist.html) to see what evidence you have completed.

## If you finish early

- Improve your README so a new contributor can take the first step without asking you.
- Rewrite one issue so every acceptance criterion can be checked.
- Use the glossary to explain the difference between Git, GitHub, a branch, and a pull request.
- Complete the final challenge in a second practice repository.
