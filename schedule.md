# Suggested run of show

This is a flexible one-day plan for **MGH-900: GitHub Foundations — September 10, 2026**. Adjust the clock to fit the class; preserve the sequence because each activity builds on the previous one.

| Block | Focus | Learner output |
| --- | --- | --- |
| Opening | What GitHub is for; repository tour | A personal practice location |
| 1 | Repositories, files, and README conventions | A repository with a clear purpose |
| 2 | Commits and branches | A focused change on a feature branch |
| Break | — | — |
| 3 | Pull requests and review | An opened and reviewed PR |
| 4 | Issues and Projects | One actionable issue in an organized view |
| 5 | GitHub Actions | A passing validation run |
| Close | Final challenge and reflection | A complete GitHub workflow |

## Facilitation notes

- Demonstrate once, then give learners time to repeat the action.
- Ask learners to narrate the intent of a change before they make it.
- Prefer the web interface for the first pass; show equivalent Git commands only after the concept is clear.
- Keep examples small enough to review in under two minutes.
- For the final challenge, grade the workflow and explanation rather than the size of the code.

## Fast recovery paths

- **Learner cannot create a repository:** use a fork of this public repository or a shared instructor repository.
- **Learner is unsure what to edit:** use starter/profile.md.
- **PR has no obvious reviewer:** pair learners and review each other's PRs.
- **Action is queued or unavailable:** inspect the workflow file and discuss what it would validate; the learning goal is understanding the workflow, not waiting on infrastructure.
