# GitHub Foundations glossary

| Term | Plain-language meaning |
| --- | --- |
| Repository | The project space containing files, history, settings, and collaboration features. |
| Git | A version-control system that records changes over time. |
| Commit | A named checkpoint that records a related set of changes. |
| Branch | A movable line of work that can be developed and compared separately. |
| Default branch | The branch GitHub treats as the main integration line, often named main. |
| Fork | A personal copy of another public repository on GitHub. |
| Clone | A local copy of a repository and its history. |
| Pull request | A proposal to merge changes, together with its review conversation and checks. |
| Review | Feedback and approval activity on a pull request. |
| Issue | A tracked question, bug, task, or improvement request. |
| Project | A planning view that organizes issues, pull requests, and other work. |
| GitHub Action | An automated workflow that runs in response to repository events. |
| Workflow | A YAML-defined automation made of jobs and steps. |
| Runner | The machine that executes a workflow job. |
| Artifact | A file or result produced by a workflow run. |
| Merge | The act of bringing changes from one branch into another. |
| Protected branch | A branch with rules that restrict or guide direct changes and merges. |
